# Contributing

toyLIFE2 is an early research preview. Contributions should make the model
easier to use, preserve documented molecular rules, and supply evidence for
changes in behavior or performance.

## Development

Clone with `--recurse-submodules`, then use Python 3.12 or 3.13:

```sh
uv sync --locked --group dev
uv run python -m pytest -q
uv run ruff check src/toylife2 tests examples
uv run python -m pyright
uv build --wheel
uv run python tests/check_wheel.py
```

CPU checks run in GitHub Actions. Apple Metal qualification requires a Mac
with Metal access; the procedure is in [qualification](docs/qualification.md).
Report the actual backend and whether fallback occurred.

## Model and experiment changes

Start with [model decisions](docs/decisions.md) and the
[runner guide](docs/runner.md). Describe any rule change, including its source,
tie handling, update order, and effect on existing records. Validate chemical
changes against the scalar reference and relevant source-derived fixtures.
Keep exploratory extensions explicit in configuration and documentation.

For bugs, include a minimal configuration or genome, seed, backend,
dependency versions, expected behavior, and observed result. Strip private
data before sharing run records: portable records include source and inputs.

For performance changes, use the [benchmark protocol](docs/cpp-benchmark.md).
Retain matched outputs, preparation and compilation costs, completed transfers,
hardware identity, and repeated timings. Give evidence for the workload being
claimed. Keep generated runs and caches outside Git; selected evidence belongs
in `evidence/` with its provenance.
